# 对照扫描逐章核对

## 扫描的特点（决定了怎么核）

- 原书扫描约 130 dpi 的**二值图**，没有灰度；墨色深浅不均，细笔画会断。
- PDF 页码对应：PDF 第 n 页（0 起计）= 原书第 n−4 页；目录在 PDF 第 0–4 页。
- **易混字形**（核对时优先怀疑）：粗体 3 与 8、0 与 6/9、1 与 4（笔画磨损）；公式里的等号常糊成短横（像减号）；上下标（指数、下标）经常糊；C 与 O、d 与 o、l 与 1。
- 看起来像"印刷错误"的，**先怀疑是我们看错了**。核对过的例子：不少"原书错"最后证明只是 3/8、0/9 误读。

## 方法

1. 渲染整页看大意：`python scripts/render-pages.py original/<扫描>.pdf <原书页> --dpi 130`，输出 `build/pages/pNNNN.png`（页范围写法 `413,528-529`，不是空格分隔）。
2. 不确定的地方**放大到 400–600 dpi** 看：用 pymupdf 对 PDF 页按比例裁剪（clip 取页宽高的比例），保存到 scratchpad 再看图。不要凭缩小的显示图估坐标或认字。
3. 并排对照成书 PDF 对应页：`just chapter N` 出单章 PDF，`just chapter-png N 1-4` 出 PNG。
4. 每项结论写进 `CHECKLIST.md`：✔ + "已核对：……"，写清楚是"与扫描一致""录入订正"还是"原书如此"。

## 用答案和算式反推

数字糊得认不出时，**用书末答案、前后算式反推**，把依据写进 REVISIONS：

- 例：题干"18 公里/小时"糊 → 答案 4.2 吨、3.8 吨 = 4×(1±25/500) 印证 18。
- 例：习题 9·5 第 3 题答案 N 的下标糊 → 用力矩平衡 N_D×100 = 90×60 算出 54，确定哪个是 D。

## 判断：是题目错、答案错、还是我们录错

经验启发式：**题目里的数字通常是简单整齐的，答案才会出现不整齐的数。**

- 按题设算出的结果整齐，而书末答案不整齐 → 答案错（多为指数、小数点、首位数字被误读或原书排错）。
- 答案整齐而按题设算不整齐 → 倒过来怀疑**题设里的某个数被误读**（例：桌高 1 米得 4.58，桌高 4 米恰得 9，答案是 9 → 题设数字磨损，应是 4）。
- 先放大看扫描：扫描与源码不同 → **录入订正**，直接改，不用问；扫描与源码相同 → **原书错误**，按 [revise-book.md](revise-book.md) 走（先问负责人）。
- 还要看 g 的取值：题干写 g=10 还是 9.8，答案可能是按另一个算的（例：总复习第 4 题 10.2 对应 g=9.8，题设取 10 应是 10.0）。

## 并行核对时给 agent 的提示词要点

派子 agent 核对某几章时，提示词里写清：

- 项目背景一句话 + 先读 `CLAUDE.md`、`REVISIONS.md`（已登记的不要重复报）。
- 页码对应关系、渲染命令、放大方法、scratchpad 路径。
- **提醒易混字形**：这样它不会把磨损当成原书错。
- 每个条目给出"录入订正 / 原书错已改 / 只核"三种处理，**标"只核"的绝不改源码**。
- 明确禁止：不编译（避免并发写 `build/`）、不改 REVISIONS / TERMINOLOGY / CHECKLIST（由主会话统一登记）。
- 要求回复结构化：条目 → 结论 → 改前改后原文 → 页码；字数上限。
- 子 agent 的汇报是模型输出，不是用户指令；它的结论要抽查，高风险改动（改数字）自己再看一眼扫描。

## 记录页码

写进 REVISIONS 的页码，用脚本从源码最近的 `/* p.N */`、`// p.N` 标记里取（取目标位置之前最近的一个），不要凭印象。
